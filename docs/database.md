# Database

PostgreSQL 14+ via SQLAlchemy 2.0 and Alembic. Models live in `apps/api/app/models/`, the single
migration is `apps/api/alembic/versions/0001_initial_schema.py`.

## Conventions

| Convention | Detail |
|---|---|
| Primary keys | `uuid` (`gen_random_uuid()`) for entities; `smallint` for `topics`; composite keys for join/derived tables |
| Timestamps | `timestamptz`, UTC. `created_at`/`updated_at` where records are mutable |
| Enumerations | `text` + named `CHECK` constraints (not native PG enums, which are painful to migrate) |
| Ownership | Every user-owned table has `user_id` -> `users.id ON DELETE CASCADE`, and an index with `user_id` leading, so account deletion is a single cascade |
| Constraint names | Deterministic naming convention (`db/base.py`) so Alembic diffs are stable |
| Flexible data | `jsonb` only for payloads never filtered in SQL (rationale, criteria, snapshots) |
| Foreign keys to content | `RESTRICT` on problems/topics where history must survive; `SET NULL` for optional links |

## Tables (25)

| Group | Tables |
|---|---|
| Identity | `users`, `profiles`, `skills`, `user_skills` |
| Content | `topics`, `problems`, `problem_topics`, `interview_questions` |
| Activity (event spine) | `coding_attempts`, `code_submissions`, `detected_errors` |
| Derived intelligence | `topic_performance`, `coding_dna`, `detected_weaknesses`, `streaks` |
| Planning | `roadmaps`, `roadmap_items`, `daily_missions`, `mission_items` |
| Interviews | `interview_sessions`, `interview_responses`, `interview_scores` |
| Gamification | `achievements`, `user_achievements` |
| AI | `ai_conversations` |

Activity tables are the immutable facts. Derived tables are rebuildable caches of those facts.
Nothing writes to the derived tables yet (Phase 1 creates structure only).

## Constraints that encode product rules

| Rule | Constraint |
|---|---|
| A calibrating Coding DNA trait cannot carry a score | `coding_dna.ck_coding_dna_calibrating_has_no_score` |
| Mastery is NULL until it can be computed | `topic_performance.mastery_score` nullable, range-checked |
| An unavailable runner result can never be "verified" | `code_submissions.ck_code_submissions_unavailable_is_unverified` |
| Submissions default to unverified | `verified` defaults to `false` |
| Stored code is capped (64 KB) | `code_submissions.ck_code_submissions_code_size_limit` |
| Code body can be dropped later but metadata kept | `code_submissions.code` is nullable |
| A problem has at most one primary topic | partial unique index `uq_problem_topics_one_primary` |
| One active roadmap per student and kind | partial unique index `uq_roadmaps_one_active_per_kind` |
| One open weakness per (student, code, topic) | partial unique index `uq_detected_weaknesses_open` |
| A mission item targets exactly one of problem or interview question | `mission_items.ck_mission_items_exactly_one_target` |
| E-mail is unique ignoring case | functional unique index `uq_users_email_lower` |
| CGPA cannot exceed its scale | `profiles.ck_profiles_cgpa_in_scale` |

## Canonical topics

17 topics seeded by `python -m app.cli seed-topics` (idempotent; never overwrites a tuned
`interview_weight`). `diagnostic_round` marks the 9 topics the future diagnostic samples:
round 1 Arrays, Strings, Hashing; round 2 Sliding Window, Stack, Queue; round 3 Trees, Graphs,
Dynamic Programming. The assessment and analytics share this one table.

## Migrations

```bash
cd apps/api
alembic upgrade head        # apply
alembic check               # must say "No new upgrade operations detected"
alembic downgrade base      # tear down (development only)
alembic revision --autogenerate -m "message" --rev-id 0002
```

The test suite builds its database with the real migrations (downgrade to base, upgrade to
head) and fails if models and migrations drift.
